How to read this example

The model has two conceptual parameter partitions, θ₀ and θ₁; their optimizer states are s₀ and s₁ for each block. Gradient and optimizer-state blocks align with the corresponding model blocks. A gradient has the same shape as its parameter, but its values and precision can differ; an optimizer may store multiple state tensors per parameter. DDP shows each model unit and state tensor as a single full shape. In the sharded views, each unit and state tensor is divided into two equal conceptual partitions; a filled segment is present on that rank. Colors identify partitions, not exact memory sizes. Primes mark updated parameters. Gradient superscripts identify the rank's local contribution. The ranks start from the same logical model and optimizer state. DDP stores full identical copies; the sharded views distribute different pieces across ranks.

Teaching model: fixed two-rank, equal-weight gradients and one optimizer update. Full sharding illustrates an FSDP-style full-shard policy that keeps parameters materialized through backward; actual implementations can reshard, gather and overlap at different times. The three illustrative blocks are treated as one wrapped unit here; actual FSDP wrapping determines the sharding granularity. The phases separate computation and synchronization for teaching; in DDP, bucket reductions can overlap backward. Activation and temporary-buffer memory are not shown.
