Inside an H100 SXM

Expand each level to follow the hardware from the whole GPU down to the scheduler modeled below.

GPU · 132 streaming multiprocessors

Eight GPU processing clusters contain 66 enabled pairs of SMs. The SMs share 50 MB of L2 cache and reach 80 GB of HBM3 through memory controllers.

One SM · four processing partitions

The SM can keep up to 64 warps resident. Registers and shared memory allocated to its thread blocks determine how many actually fit.

One partition · one warp scheduler

The scheduler issues instructions from ready warps. This partition has 32 FP32 arithmetic lanes, one Tensor Core, and its own portion of the SM’s register file.

For a load from device memory with L1 caching enabled, each cache miss sends the request to the next level.

Schedule four warps

Each warp issues a load. Its add becomes ready six ticks later. Change how many warps can be resident together. A resident warp has resources on the SM and can issue an instruction when it is ready.

L = load, W = waiting for data, R = ready to issue, A = add. A dash marks a queued or completed warp.

This model isolates one scheduler, with a single issue slot per tick. Warps enter individually and release their slot after the add. The H100 admits whole blocks and its load latency varies with the memory path.
